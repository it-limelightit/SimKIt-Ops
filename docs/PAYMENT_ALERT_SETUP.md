## One-time Gmail setup

1. Sign into **it@limelightit.io** and open <https://script.google.com/home/start>. Create a new project named **SimKit Payment Monitor**.
2. Replace the default `Code.gs` contents with the complete private file **`.tmp/payment-email-monitor-ready.gs`** from this workspace. This file is generated by the deployment script with the correct endpoint and signing secret. Keep the file and Apps Script project private.
3. In Apps Script **Project Settings**, enable **Show appsscript.json manifest file in editor**. Open `appsscript.json` and replace its contents with **`integrations/payment-email-monitor/appsscript.json`**. Save. This enables the Gmail advanced service and read-only Gmail permission. If using a custom Google Cloud project, enable Gmail API there too.
4. Choose **configureAndInstallPaymentMonitor** in the function dropdown and click **Run**. Review Google's permissions and authorize your own script using **it@limelightit.io**. If Workspace blocks authorization, ask its administrator to permit the script.
5. Confirm the execution finishes successfully. The **Triggers** screen should show **checkContaboPayments**, time driven, every five minutes. Running setup again replaces this script's own existing monitor trigger; other triggers are retained.
6. Open SimKit using one of the three allowed accounts. The global **Payment Alerts** button opens **Active** and **History** tabs. After successful Gmail setup the panel shows a recent **Last Gmail check** timestamp. If testing the live Vercel website, publish the frontend changes first using the project's normal deployment flow.

No Apps Script web-app deployment, paid OCR/AI service, Gmail password, Gmail forwarding rule or PC worker is required. Do not enter a Supabase service-role key into Apps Script. Its dedicated signing secret is already saved in Supabase and the private setup file.

## Matching and behavior

Temporary test-sender support has been removed. Only genuine Contabo payment-warning emails received in it@limelightit.io are accepted. Replace the Google project's Code.gs with the current regenerated private setup script and run configureAndInstallPaymentMonitor to restore its original scan and clear the old test property. The manifest stays unchanged. Earlier test-alert history is retained and labeled as test email; it can be resolved through the existing UI.

- Sender must be exactly **no-reply@contabo.com**; the subject must begin **Contabo: Payment missing**, case insensitive. The example “Contabo: Payment missing - Avoid service suspension and data loss! Act now!” matches.
- Searches all Gmail folders, including archived/read emails, spam and trash. The first run checks the last 30 days. Previously paid warnings can therefore appear initially; confirm their payment and resolve those alerts yourself.
- Scans run about every five minutes, subject to Google's scheduling and service availability. Open SimKit pages refresh alerts every 30 seconds and when refocused.
- While a reminder is unpaid, a light red tint gently pulses across the whole app and a full-width red banner opens Payment Alerts. Controls remain clickable. Reduced-motion settings disable the pulse. **Mark as seen** records the first acknowledgment and keeps the warning active; confirming payment clears it once no active reminders remain.
- **Payment completed** asks for explicit confirmation, records who confirmed and when, and clears that reminder for everyone. It records your confirmation; it neither makes a payment nor verifies Contabo's receipt.
- Duplicate scans of the same email never reopen a resolved alert. A new warning email produces a new active alert, including a new message in an old Gmail thread.
- The **History** tab shows the most recent 100 resolved reminders; older rows and action events remain stored in Supabase.
- The panel warns if setup is incomplete or there has been no completed Gmail check for 20 minutes. Check Apps Script **Executions** for permission, quota or connection failures. The Gmail cursor advances only after a whole scan succeeds; failed scans retry without losing alerts.

## Data and limits

Only matching message IDs, sender, subject, received time and short preview are stored. Bodies and attachments are not downloaded or stored. Gmail access is read-only: the script never sends, deletes, moves or marks emails read. Browser permissions and database permissions both restrict access to the three addresses. Ingest calls use timestamped HMAC signatures; the signing secret is never included in frontend assets.

This uses existing services without adding a paid subscription. Google Apps Script and Supabase usage quotas still apply; it is not a guarantee of uninterrupted monitoring. A scan permits up to 500 search results, sends bounded batches and stops without advancing the cursor if that limit is exceeded.

Google references: [time-driven triggers](https://developers.google.com/apps-script/guides/triggers/installable), [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas), [advanced-service setup](https://developers.google.com/apps-script/guides/services/advanced), [Gmail read-only scopes](https://developers.google.com/workspace/gmail/api/auth/scopes).
